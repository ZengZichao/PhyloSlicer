provenance = Every file below is a treesliceR reference value used by validation/compare.py and, for the *__CpD.csv / *__CpE.csv rate files, by the CLI `validate` subcommand.  They were produced OUTSIDE this checkout by the generator named above (its SHA256 is recorded so the pairing is auditable) against treesliceR 1.1.0, and are pinned here by SHA256 so a comparator can tell a registered external reference from an ad-hoc CSV. compare.py refuses to run at all when a file it wants to read has no entry here, or when the bytes on disk differ from the registered hash, and the CLI refuses an unregistered --reference for the same reason.  Neither will transpose a file to make it fit: shape and column names are checked against the recorded orientation, and a mismatch is a hard error. generator_sha256 describes the script AS OF the date above; the criterion="PD" block added for the equal-PD criterion postdates the CSVs and produces no files that exist here, so refresh this hash whenever the script changes again.
limitations = RESOLVED 2026-09-21 - the per-slice profile files.  They used to be recorded as status = unverified because every committed copy was slice-by-site with 30 columns while validation/r/generate_reference.R writes site-by-slice with 50, and R was not installed to settle which of the two was wrong.  R is installed now: running the committed generator reproduced all 21 time-criterion reference files byte-for-byte (three trees, six matrices, twelve CpD/CpE CSVs) and wrote 30x50 profiles, so the committed profiles came from an older revision of the script and the regenerated ones are registered here.  The superseded files are not part of the repository; the re-run recorded here is the evidence.  What this does NOT buy: the equal-PD criterion is still not cross-validated, because the criterion = 'PD' calls fail inside treesliceR 1.1.0 itself on these inputs (18 warnings, no *_PD.csv written, 'length of dimnames not equal to array extent'), and CpB and the pairwise/multisite beta families were never fed to the reference at all.  The hashes below still detect after-the-fact edits of a CSV; they do not by themselves re-derive the claim that a given CSV is what the committed script writes, which is why the byte-identity of the 21 companions is recorded in each profile's note.  EXTENDED 2026-09-21 - the beta families.  CpB, CpB_RW and r_phylo(index = 'PB') are now generated by the same script and the same R run that reproduced the 33 registered files byte-for-byte, so beta is a cross-implementation comparison rather than an internal invariant.  Three things it still does not buy: (a) three beta families produce no reference at all, because treesliceR 1.1.0 fails on them (CpB sorensen/pairwise aborts in nls; r_phylo PB sorensen- and turnover-pairwise return a ragged k x P list); (b) the CpB *rate* for the turnover and nestedness components is an accepted divergence - phyloslicer re-normalises the profile to sum to 1 while the reference fits cumsum(series)/total, and for turnover/pairwise the reference's own curve is in addition method-independent (CpB.R:605 reduces to CpB.R:609); validation/compare.py scores both conventions side by side and reports them as 'documented divergence' rows, never as passes; (c) none of this is equal-PD slicing, which still yields no reference - although this run also showed that its failure is 'object cutted_tree not found' for the documented spelling criterion = 'PD' (phylo_pieces compares 'pd' in lower case), not the dimnames error recorded when that block was first run.  The hashes below still detect after-the-fact edits of a CSV; they do not by themselves re-derive the claim that a given CSV is what the committed script writes, which is why the byte-identity of the companions is recorded in each new file's note.
beta_families = CpB(comp, method) x {sorensen, turnover, nestedness} x {multisite, pairwise}; CpB_RW(method) x {multisite, pairwise}; r_phylo(index='PB', comp, method). Three of those produce no reference because treesliceR 1.1.0 itself fails on them - CpB__sorensen_pairwise (nls: "'qr' and 'y' must have the same number of rows") and rPB__{sorensen,turnover}_pairwise (ragged k x P output) - see validation/NOTES.md
